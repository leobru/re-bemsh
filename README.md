# re-bemsh

Восстановление и разбор транслятора **ИПМ МАКРО-БЕМШ ВЕР.06/78**, которым
`re-dispak` транслирует модули ОС (`re-dispak/asm.pl`). Исходников нет;
код снят с диска 2048 и дизассемблирован.

Пометки: **[трасса]** — проверено потактовой трассой dispak, **[опыт]** —
проверено заданием, **[код]** — прочитано в коде.

## Как вызывается

Задание `asm.pl` (его же делает `tools/job.pl`) объявляет
`лент 30(2048-6200)`, кладёт с 04000 загрузчик
`сч 4003 / уиа 4000(М15) / Э66 1` и текст карт с 014000:

```
ВВД$$$          начало текста
 ...текст...
КВЧ$$$          конец текста
ТРН$$$          трансляция
ЧТКОМП420070    библиотека макросов: лента 42 (2099), зона 070
1-1             какие строки печатать (0-0 - все)
ЗОНМОД430000  0004
КНЦ$$$
```

Номер зоны dispak берёт по маске `& 0xfff` (`dispak/extra.c:3367`), поэтому
зона ленты 30 `01747` — это 2048, зона `(01747 + 06200) & 07777 = 0147`.
Код БЕМШ — 2048, зоны **0147–0177** (по каталогу 2048 — «транслятор с М/К
БЕМШ», 20.06.78). Зоны 0160, 0163, 0164, 0167 пустые (разметочный код),
0175 — почти одни нули; ни в одном прогоне они не грузились.

Снята `tools/trace.sh` + `tools/phases.py` (`traces/*.ev`); адреса — где
стоит `Э70`.

| | 01217–01222 | 0150 → 070000, 0151 → 074000, 0152 → 076000 | ввод и разбор управляющих карт, текст на барабан 012 |

| макрокомпилятор «ОТ 2.8.78» | 01305–01306 | 0165–0166 → 02000 | только при `ЗПКОМП`: компиляция определений в библиотеку |

зонами 0153/0157, монитор их не восстанавливает.

## Входной язык макросов [опыт]

- Определения `МАСRО … МЕND` пишутся в начале текста, **перед `СТАРТ`**;
  первая строка `МАСRО` (`jobs/inmac.be`). `ПЕЧМАК`, `БЛМАК` — управляющие
  карты после `ТРН$$$`, а не строки текста.
- `ЗПКОМП430070` после `ТРН$$$` компилирует определения (`dispak/dispak/macros.b6`)
  в библиотеку на 2099, зону 070; `ЧТКОМП420070` её подключает.
- Без `ПЕЧМАК` строки раскрытия не печатаются, но номера строк листинга
  их учитывают (0010 → 0014).

## Макроредактор (`mred2`, `mred74`, `mred24`)

Части: `mred2` (02000–07777) — основной код; `mred74` (074000–077777) —
таблицы, буферы и лексические подпрограммы, их вызывает только эта фаза
[трасса]; `mred24` (024000–027777) — библиотека последовательного обмена
(«ОБМУПД», «ДАЙ БУФ», «НЕТ ДАН»), её вызывает и макромашина (вход 26727)
[трасса]. Размеченные исходники: `parts/mred2.be`, `parts/mred74.be`
(разметка — `notes/*.py`, сборка `tools/mkbe.py`).

### Что на входе и на выходе [трасса, опыт]

- **Текст** — на барабане 012, по записи на строку (`jobs/inmac`, снимки
  `tools/snap.sh` в 05756 и 06006). Заголовок записи:
  `2000 0001 0005 2003` — признаки, номер строки, (?), длина записи в
  словах (мл. байт). Дальше поля строки без пробелов, разделитель —
  байт 01, пустая метка — байт 00; литеры в 8-битном коде (ASCII + 040:
  пробел 0100, `&` 0106, `'` 0107, `(` 0110, `,` 0114, `.` 0116, цифры
  0120–0131; буквы 0240–0337). Последняя запись — `*КОНЕЦ ЧАСТИ`.
- Редактор читает записи в 072000, правит **только заголовки** и пишет
  их обратно: ставит бит `0010` в первой группе (`2000…` → `2010…`)
  строкам, которые обработает макромашина (определения макросов, вызовы
  макросов, `*КОНЕЦ ЧАСТИ`), и номер ошибки (`ОШИБКА`, 04567).
- **Библиотека** `ЧТКОМП420070` читается с ленты 42 (2099), зоны 070–075 в
  010000–023777 и 076 в 030000 (`ЧТБИБ`, 03040). Её хвост 023700–023777 —
  головы хеш-цепочек общей таблицы имён, пул пар «имя, связь» — с 010000.
  Редактор дописывает туда новые макросы (42 слова в 010767–011275 и
  заголовок 023675–023677 в опыте с `СЛОЖИ`).
- **ГС** (по выдаче «КОЛИЧ ЯЧ ГС» — «ячейки ГС») — скомпилированные
  определения и вызовы для макромашины, в памяти с 032000 вслед за ГС
  библиотеки (030000). Первое слово блока — длина; элементы с заголовком
  `тип, номер строки, длина` (`0040 0003 0000 0005` — строка 3 тела
  `СЛОЖИ`). Формат элементов ещё разбирается.

ГС задания `jobs/inmac` (снимок перед загрузкой макромашины, 032000;
тип — старшие 12 бит заголовка, длина — младшие) [опыт, смысл полей —
предварительно, проверить по макромашине]:

```
032000  длина блока 072
032001  0040 стр.3  дл.5  &М СЧ &А    текст строки, параметры как {040}{номер}
032006  0040 стр.4  дл.5  СЛ &Б
032013  0000 стр.5  дл.3  АIF         скомпилированное условие
032016  0040 стр.6  дл.5  ЗП &Б
032023  0000 стр.010 дл.2 МЕND
032025  описатель макроса: 3 параметра, ... 023
032031  0020 стр.1   ... {200}{010}   переписать 8 строк (само определение)
032034  0020 стр.011 ... {200}{2}     СТАРТ и строка вызова
032037  0100 стр.012 дл.010  вызов с меткой: СЛОЖИ, X, Y, Z, описатели
032047  0020 стр.013 ... {200}{1}
032052  0040 стр.013 дл.5   вызов без метки: СЛОЖИ, Y
032057  0020 стр.014 ... {200}{1}
032062  0020 стр.014 дл.3   вызов без аргументов: СЛОЖИ
032065  0020 стр.015 ... {200}{4}     КОНД, ПАМ, ФИНИШ, *КОНЕЦ ЧАСТИ
032070  0007 7777           конец
```

То есть основная программа превращается в чередование «переписать n
строк исходника» и «раскрыть вызов».

### Разбор оператора [код, частично опыт]

`ОПЕРАТ` (03453) берёт очередную запись (`ЧТЗАП`, с заглядыванием на
одну вперёд — для продолжений) и по первой литере выбирает вид метки:
`&` — оператор `SЕТх` (`ПЕРМЕТ`), `.` — порядковая метка (`ПОРМЕТ`),
`*` — комментарий (`КОММ`), буква — обычная метка, иначе метки нет.
Код операции ищется в общей таблице (`ОПКОД`, подпрограмма `ВГЛОБ`):
найден макрос — компилируется вызов; найдена директива — переход по её
номеру (`ДИРЕКТ`, 04670); не найден — обычная команда ассемблера.

Директивы и их обработчики [опыт, `jobs/dir/*`]:

| № | Директива (рус.) | Обработчик |
|---|---|---|
| 0, 1 | `МАСRО` (`МАКРО`), `МЕND` (`МФИН`) | `ДМАКРО` 04741, `ДМЕНД` 05226 |
| 2, 3 | `МЕХIТ` (`МВЫХ`), `МNОТЕ` (`МРАСП`) | 05353, 05357 |
| 4–7 | `АNОР` (`АНОП`), `АGО` (`АПБ`), `АIF` (`АПУ`), `АСТR` (`АСЧЕТ`) | 04526, 05405, 05434, 05466 |
| 8–13 | `GВLА`, `LСLА`, `GВLВ`, `LСLВ`, `GВLС`, `LСLС` (`ГБЛ…`, `ЛКЛ…`) | 05471–05476 |
| — | `SЕТА/В/С` (`УСТА/В/С`) | по метке `&` (03566) |
| 17 | `SRСН` (`ПОИСК`) | `ДПОИСК` 05664 (метка — переменная, как у `SЕТх`) |
| 18? | `SМОDЕ` (`СРЕЖ`), `СОРY` (`КОПИ`, `КОПИР`) | 04716 — не проверено |

Имена директив лежат в `ТДИР` (074441, латинское и русское подряд).
Ошибки: входы 04532–04566 кладут в М16 номер (0160–0344 с шагом 2),
`ОШИБКА` пишет его в заголовок записи; текст печатает листинг (например,
«МАКРО С ОШИБ», «НЕДОПУСТ ВЫР»).

## Макромашина (`mmash`, 0170–0171 → 02000)

Размеченный исходник: `parts/mmash.be` (`notes/mmash.py`). Пользуется
библиотекой обмена `mred24` и подпрограммами потоков записей резидента
(`ВХЗАП` 01513, `ВХПОЗ` 01522, `ВЫХЗАП` 01636) [трасса].

### Что делает [трасса, опыт]

Исполняет ГС: исходные записи переписывает из входного потока (барабан 012)
в выходной (барабан 013, с зоны 010 — `jobs/inmac`, лист 03 перед записью
в 01714), а на месте вызовов вставляет сгенерированные записи. У
сгенерированной записи в заголовке номер строки-образца из определения и
признак в третьей группе (`0000 0003 4005 2003`); листинг показывает его в
колонке «N ГЕН» как `+0003+`. Выход читает ассемблер.

### Устройство [код + трасса]

Стековая машина с побайтным кодом (`БАЙТ`, 02411): М12 — слово ГС, М13 —
сдвиг байта. Байт `01xxxxxx` — команда номер `xxxxxx`; любой другой байт
начинает двухбайтный операнд `(б1·256 + б2) XOR 0100000`, который кладётся
в стек (М17):

| Операнд | Смысл |
|---|---|
| `010xxxx` | кусок текста номер xxxx из текстовых слов элемента |
| `011xxxx` | глобальная переменная или строковая константа |
| `012xxxx` | параметр, местная переменная или порядковая метка номер xxxx (3 — параметр-метка, затем позиционные и ключевые параметры, местные переменные, метки) |
| `00xxxxx` | число |

Выбор команды (`ВЫБОР`, 02001) — двойная модификация: `МОД КОМ`, `МОД ТКОМ`,
`ПБ`; слово таблицы `ТКОМ` (02003) — `ПВЛ ВХКОМ / ПБ обработчик`. Имена
команд лежат в `ТИМКОМ` (02074) для трассировки (печать `ПЕЧ…`, 05142–05300,
включается ячейкой `ТРАСС`; как её включить, не прослежено).

| № | Команды |
|---|---|
| 0–17 | `КВС AIF SET ВС ВДЧ MEND ПГП ПС КНК ИНДВ ИНДЗ ЗПС ЗПСГ КЛЧ ВЫД КОНЕЦ` |
| 020–025 | `EQ GT GE NE LT LE` (числа) |
| 026–036 | `АТРN ACTR СЛ ВЧ УМН ДЕЛ NOT AND OR` |
| 037–046 | `АТРК АТРР АТРL АТРС SRCHA SRCHC КНКП КОШ` |
| 047–055 | `AGO TEQ TGT TGE TNE TLT TLE` (строки) |
| 056–064 | `БЛОК ВС0 ЗПСУ АТРУ MNOTE АТРМ АТРА` |

### Формат ГС [опыт, `tools/gs.py`]

Блок: первое слово — длина; затем элементы. Заголовок элемента: число
текстовых слов (старшие биты; `0020` — 1, `0040` — 2, `0100` — 4), номер
строки исходника, (?), длина элемента в словах. За ним текстовые слова
(8-битный код), затем байт-код. После тела макроса — описатель (элемент с
«номером строки» 4000: число параметров, умолчания ключевых и др., не
разобран).

Компиляция (макрос `ТЕСТ` из `jobs/rich.be`; выдача `tools/gs.py`):

| Строка | Байт-код |
|---|---|
| `&СЧЕТ SЕТА &СЧЕТ+1` (`GВLА &СЧЕТ`) | `к1272 к1272 1 СЛ SET` |
| `&Л SЕТА &К*2-1` | `п10 п6 2 УМН 1 ВЧ SET` |
| `&С SЕТС 'Х&А'` | `п11 т0 п4 2 КНК SET` |
| `АIF (N'&Б GТ 1).ЕСТЬ` | `п5 АТРN 1 GT п12 AIF` |
| `МNОТЕ 'НЕТ Б'` | `0326 КОШ т0 ВДЧ` |
| `АGО .ВСЕ` | `п13 AGO` |
| `&М СЧ &Б(2)` | `п3 т0 п5 2 ИНДВ т1 4 КНК ВДЧ` |
| `МЕND` | `MEND` |
| (осн. программа) 2 исходные строки | `2 ПГП` (текстовое слово — адрес записи) |
| `А ТЕСТ Х,(Y,Z),К=3` | `т0 ВС т1 ЗПС т2 ЗПС т3 т4 2 ЗПСГ ЗПС т5 КЛЧ т6 ЗПС КВС` |
| ` ТЕСТ Q` (нет метки) | `т0 ВС ПС т1 ЗПС КВС` |
| конец текста | `КОНЕЦ` |

`т` — кусок текста, `п` — параметр/переменная, `к` — глобальная (по
`tools/gs.py`). Результат раскрытия совпадает с IBM-подобной семантикой:
`N'&Б` для `(Y,Z)` = 2, `&Б(2)` = `Z`, ключевой `К=3` перекрывает
умолчание, глобальный счётчик растёт между вызовами, `SЕТС 'Х&А'` → `ХХ`.

### Память и кадр вызова [трасса, снимок]

Динамическая память — с 074000 (таблицы макроредактора там уже не нужны),
стек операндов — с 077000 (М17). Снимок `tools/snap.sh jobs/inmac.b6 03621`
(первая `ВДЧ` в раскрытии `X СЛОЖИ Y,Z`): `КАДРВ` (01205) = 074016,
`КАДРН` (01206) = 074002, М12 = 032005 (текущее слово ГС):

```
074003  0020 0001 27 074000   связь с предыдущим кадром
074004  0000 4037 0000 4000   место вызова в ГС (элемент 032037)
074006  02 ... 074013          п3 = &М -> строка "X"
074007  02 ... 074014          п4 = &А -> "Y"
074010  02 ... 074015          п5 = &Б -> "Z"
074011  12 ... 274007          п7 - порядковая метка .К
074012  023                    описатель макроса: 032002+023 = 032025
074013… "X" "Y" "Z"            значения аргументов (8-битные строки)
074016  "X СЧ Y"               строка, собранная КНК для ВДЧ
077000… описатель этой строки, затем операнды т0 п4 т1 4
```

Значение хранится описателем: `02…` — строка (адрес), `12…` — метка
(смысл остальных полей кадра — по коду `ОВС`/`ОКВС`, не дочитан).

### Команды по обработчикам [код; поведение — опыт]

| Команды | Что делают |
|---|---|
| `ВС` (02554) | ищет макрос по имени (`ИЩМАК`); нет — ошибка (04042), ГС макроса = 0777777 (определение с ошибками) — «МАКРО С ОШИБ» (04047); строит кадр в памяти М4: имя, связь, ячейки параметров («пусто»), умолчания ключевых, номер вызова `&SNDX` (десятичный счётчик `D02207`) |
| `ЗПС`, `ПС` | аргумент в текущую ячейку (текст копируется в память), пустой — пропуск; лишний непустой позиционный — ошибка (04013) |
| `ЗПСГ`, `ЗПСУ` | подсписок из n значений (вектор описателей); маркер вложенного подсписка |
| `КЛЧ` | следующая `ЗПС` — в ячейку ключевого параметра с этим именем; нет такого — ошибка (04061) |
| `КВС` | кадр готов: `КАДРВ`, число позиционных (`N'&SLIST`), адрес ГС и имя макроса; исполнение тела |
| `ПГП` | переписать n исходных записей во выходной поток |
| `КНК`, `КНКП` | сцепить n значений в строку |
| `ВДЧ` | строку — новой записью в выходной поток (с кодом ошибки от `КОШ`, если был) |
| `SET` | значение — в переменную |
| `AIF`, `AGO`, `ACTR` | переход по ГС; счётчик переходов; превышение `АСТR` — «ЦИКЛ В МАКРО» и **конец работы макромашины**, остаток программы теряется (опыт `jobs/ctl.be`) |
| `MEND` | возврат по кадру к вызывающему элементу |
| `СЛ ВЧ УМН ДЕЛ`, `NOT AND OR`, `EQ…LE` | над числами (`ОПЧИС`: текст разбирается как десятичное число, не число — «НЕ ЧИСЛО»); истина = 1 |
| `TEQ…TLE` | сравнение строк посимвольно (04244) |
| `ИНДВ`, `ИНДЗ` | элемент подсписка `&Б(2)` |
| `ВЫД` | подстрока `'&А'(2,2)` → `БВ` для `АБВГД` |
| `КОШ`, `MNOTE` | код ошибки для следующей выдачи; `МNОТЕ` без уровня — «СООБЩ ОБ ОШ» (0326) |
| `КОНЕЦ` | вернуть лист 034 монитора с барабана 010, дописать выходной поток (01721), выйти в монитор (01214) |
| `SRCHA`, `SRCHC` | поиск в массиве переменных, см. ниже |
| `БЛОК`, `ВС0` | служебные (не разобраны) |

Поиск `SRСН` (`ПОИСК`) [опыт `jobs/srch.be`, код `ДПОИСК` 05664 и
`ОПСКА`/`ОПСКС` 03506–03565]:

```
&П SRСН &МАС,образец)(нач,кон,шаг).МЕТКА      -> SRCHA
&П SRСН &МАС,образец)(нач,'стоп',шаг).МЕТКА   -> SRCHC
```

Ищет образец в массиве символьных переменных (`LСLС &МАС(5)`), перебирая
элементы от `нач` с шагом `шаг` до номера `кон` (`SRCHA`) или до элемента,
равного `'стоп'` (`SRCHC`; вариант выбирается по наличию строки в скобках).
Найден — номер элемента в `&П`, оператор за `SRСН` выполняется дальше; не
найден — `&П` = 0 и переход на `.МЕТКА` (компилируется как `… SRCHA п7 AGO`,
при удаче `AGO` пропускается). Сравнение — слово элемента целиком (`'ВХ'` не
совпадает с `'В'`). Шаг может быть отрицательным, но только выражением или
переменной (`0-1`, `&Ш`; запись `-1` в скобках отвергается). Скобки
несимметричны — так устроен разбор: после запятой `ПОДВЫР` подставляет
открывающую скобку сам. Числовой массив (`LСLА`) так не ищется: образец
переводится в текст, а элементы хранятся числами (опыт: 20 не найден).

Атрибуты (`jobs/attr.be`; аргументы `АВС` / `12` / пусто / `СТАРТ`):

| Запись | Команда | Значение |
|---|---|---|
| `N'` | `АТРN` | число элементов: 1 / 1 / 0 / 1 |
| `К'` | `АТРК` | число литер: 3 / 2 / 0 / 5 |
| `Р'` | `АТРР` | тип: U / N / O / U (как `T'` в IBM) |
| `С'` | `АТРС` | тип: U / F / U / U |
| `L'` (лат.) | `АТРL` | значение из общей таблицы: 0 |
| `У'`, `М'`, `А'` | `АТРУ`, `АТРМ`, `АТРА` | признаки: 0, 0, 1 |

Не поддерживаются: `Т'`, `Л'`, `S'`, `I'`, `D'` («САМООПР ВЛЧ»).

Системные переменные (имена — в `mred2`, 06304 и 06313): `&SNDX` — номер
вызова (3 цифры: 001, 002, …), `&SLIST` — список позиционных аргументов
(`&SLIST(2)`, `N'&SLIST`). Имя переменной — не длиннее 5 литер после `&`
(`&SYSNDX` — «ТЕРМ >6 СИМВ»). Аргументы вложенного вызова передаются
текстом (`ВНУТ &Н/2` → `3/2`); рекурсия работает (через `SЕТА`), без
выхода — до «ПЕРЕП ЛОК СЛ» (`jobs/ctl.be`).

Ошибка макромашины (`ОШМАШ`, 04652) — отдельная запись выходного потока
(номер строки, код, признак «сгенерировано», текст `***** //////` и имя
макроса); листинг печатает её как `МАКРО С ОШИБ … +0010+***** ////// СИС`.
Коды: 0262, 0172, 0276, 0300, 076, 0254, 0302, 0260, 0274, 0312 («НЕ
ЧИСЛО»), 0304 (константы 05526–05540); тексты печатает листинг, в зонах
БЕМШ их в 8-битном коде нет — где они, не найдено.

Подпрограммы: `ИЩМАК` (04113, имя в общей таблице 023700), `ОПЧИС`/`ОПТЕК`/
`ОППЕР`/`ОПКУС` (операнд со стека как число, текст, ячейка, кусок),
`ОШМАШ` (04652, ошибки), `ОПГП` (переписывание через `ВХЗАП`/`ВЫХЗАП`),
`ОВДЧ` (выдача сгенерированной записи), `ОМЕНД` (возврат из раскрытия,
кадры от ячеек `КАДРВ`/`КАДРН` резидента).

## Ассемблер (`asmc`, `asm1`, `list`)

Два прохода [трасса `jobs/asm1.be`, снимки]:

| Фаза | Части в памяти | Вход → выход |
|---|---|---|
| первый проход | `asmc` (0172 → 02000) + `asm1` (0173–0174 → 04000) | записи макромашины (барабан 013) → те же записи с 3 доп. словами (барабан 012) |
| второй проход | `asmc` (остаётся) + `list` (0176–0177 → 04000) | записи первого прохода → листинг, таблица меток `*МЕТ*`, объектный модуль в 010000 → `ЗОНМОД` (07056, лента 43) |

`asmc` (02000–03777) — общая часть: лексемы (`ЛЕКС`, 03160…), выражения
(`ВЫРАЖ`, 03466), её вызывают оба прохода.

### Таблица операций [снимок `parts/asm1.bin`]

`ТИМОП` (04673…) — 0371 имя, `ТСВОП` (05264…) — слова свойств, хеш-головы
`ХОП` (05655), строится в начале прохода (`ХЕШОП`). Имена: русские
мнемоники и директивы, латинские в стиле Мадлена (`ATX XTA UTC UJ VJM …`),
IBM-подобные директивы (`START EQU ENTRY EXTRN USING DROP LTORG ORG EJECT
SPACE TEXT LIST BEGL ENDL`), экстракоды (`Э50…Э77`, `*50…*77`, `SIN SQRT
ARCTG …`), формы данных (`ДК ДКБ КК ККБ`), коды `Н1 Н2 П1Н ПШ …`.

Слово свойств: признак «поле регистра — приёмник» (`УИА`, `СЛИА`, `ПВ`,
`ЦИКЛ`, `ПИО` …), класс, код операции, адрес обработчика первого прохода.
Классы: 01 `ЛИСТ`, 02 команда с коротким адресом, 03 с длинным, 04 `КОНК`,
05 `КОНД`, 10 `УПОТР`, 11 `ОТМЕН`, 12 `ТЕКСТ`, 13 директивы (`ЭКВ`,
`ВНЕШН`, `СТАРТ`, `КОД`, `ОПАМ` …), 14 `ПАМ`, 15 `АДРЕС`/`ORG`, 16 `СТРН`,
17 `СТРОК`, 20 `ЛИТЕР`, 21 `ФИНИШ`, 22 `ВХОДН`, 23/24 `НАЧУР`/`КОНУР`.
Обработчик `ДПРАВ` (04231) получают `ПВ` и экстракоды — они всегда в
правой половине; `ДЛЕВ` (04234) — `ПВЛ`, `Э66`, `СП` (левая половина).
Это те самые правила, на которые опирается `tools/stripmoda.py`.

### Обработчики первого прохода [код; опыт `jobs/asm2.be`]

Счётчик размещения `СЧЕТ` (073264): адрес, знаковый разряд — правая
половина слова (`ПОЛСЛ`), разряд 47 — вставлен заполнитель, 0100000 —
относительный. Двигают его `ВЫРАВН` (на начало слова), `ПОЛПЛ` (полуслово),
`ВПРАВ` (в правую половину), `СЧЕТПЛ` (+n слов). Каждый оператор кончается
в `КОНОП1`: в запись дописываются `СЛОВО1`, `СЛОВО2`, `СЧЕТ`.

| Обработчик | Операции | Что делает |
|---|---|---|
| `ДКОМ` | команды | метка = счётчик, адрес и регистр (`ОПРЕГ`), +полуслово |
| `ДПРАВ` / `ДЛЕВ` | `ПВ`, экстракоды / `ПВЛ`, `Э66`, `СП` | сначала в правую половину / выравнивание на слово |
| `ДСТАРТ` | `СТАРТ` | только первым; абсолютный операнд — начальный адрес, без операнда — относительный модуль |
| `ДЭКВ` | `ЭКВ`, `EQU` | нужна метка; выражение без ссылок вперёд (опыт: `А ЭКВ Б+1` до `Б` — «НЕОП МЕТ») |
| `ДПАМ` | `ПАМ`, `DS` | выравнивание, +значение слов (опыт: `ПАМ Б-2` = 3) |
| `ДКОНД`, `ДКОНК`, `ДТЕКСТ` | данные | размер считает общая часть (02260, 02255, 02626) |
| `ДАДРЕС` | `АДРЕС`, `ORG` | счётчик = значение; абсолютное — предупреждение «ОПРНД АБСОЛ», но адрес ставится |
| `ДВХОД` | `ВХОДН`, `ENTRY` | признак входа у символов |
| `ДВНЕШ`, `ДВНЕШД` | `ВНЕШН`/`EXTRN`, `ВНЕШД`/`EXTRD` | метка — имя модуля, имена — в таблицу внешних `ТВНЕШ` (024000), счётчик `ЧВНЕШ` |
| `ДОПАМ`, `ДОЛПАМ` | `ОПАМ`, `ОЛПАМ` (`LC`, `PC`) | общая память по имени и размеру — в `ТВНЕШ` |
| `ДВЭКВ` | `ВЭКВ`, `CEQU` | эквивалентность во внешней таблице |
| `ДУПОТР` | `УПОТР`, `ОТМЕН` (`USING`, `DROP`) | только разбор операнда; база учитывается во втором проходе |
| `ДЛИТЕР` | `ЛИТЕР`, `LTORG` | выдача накопленных литералов |
| `ДФИНИШ` | `ФИНИШ`, `FIN` | выравнивание, последняя запись, литералы, возврат в монитор (01250) |
| `ДЛИСТ` | `ЛИСТ`, `LIST` | `ВКЛ`/`ВЫКЛ` (`ON`/`OFF`), второй операнд `ГЕН`/`НЕТГЕН` (`GEN`/`NOGEN`); пустой — без изменений (`ЛИСТ ,НЕТГЕН`) |
| `ДДК`, `ДКК` | `ДК ДКБ КК ККБ` | команда-слово из полей |
| `ДКОД` | `КОД` | запись как есть |
| `ДНОП` | `НОП` | только метка |
| (`КОНОП1`) | `СТРН`, `СТРОК`, `НАЧУР`, `КОНУР` | в первом проходе ничего, кроме записи |

### Запись первого прохода [снимок в 01714]

К каждой записи после заголовка добавлены 3 слова (длина в заголовке +3):
шаблон машинной команды (код операции), разобранный операнд (ссылка на
символ, напр. `{166}X`), адрес и половина слова (`…{2}{0}` — 01000 левая,
`…{2}{1}` — правая). У строк определения макроса слова нулевые.

### Таблица символов [снимок в конце первого прохода]

Имя символа i — в 070000+i (8-битное, дополнено пробелами), значение — в
072514+i (ёмкость ~01356 имён, на месте монитора, листы 034–036).
Слово значения: младшие 15 бит — значение; 0100000 — абсолютное (`А` в
`*МЕТ*`); средние разряды — признаки входа (`В`) и внешнего (`СА`, значение
— номер внешнего); старшие растут в порядке определения в тексте (ссылка
на место определения). Счётчик размещения — значение символа 0550
(ячейка 073264, поэтому код обращается к `'73264'`).

### Второй проход и объектный модуль

Переход по классу (`КЛАСС2`, 04132, таблица с 04135). Модуль собирается в
010000 в формате, который разбирает `disbesm6 -r` (заголовок: 1, имя,
адрес, диапазон, число кусков, длина, ВХОД, ВНЕШ; куски по 12 слов;
таблицы ВХОД и ВНЕШ) — проверено: `disbesm6 -r` по снимку листа 04 даёт
исходник с `ВХОД ТОЧКА` и `ВНЕШ ВНП,ВНД`. `ЗПМОД` (07033) пишет зоны по
`ЗОНМОД` и печатает «МОДУЛЬ … ЗАПИСАН В ЗОНЫ С … ПО …».

Наблюдения по `jobs/asm1.be`: `Б`, `Е`, `М` в начале модулей `re-dispak` —
библиотечные макросы (`Е1…Е48` и `М1…М35` через `ЭКВ`), без `М` имена
регистров не определены («НЕОПР ИНДЕКС»); `УПОТР ПР(М7)` даёт адресацию
от базы (`СЧ КОНСТ` → `07 010 0004`); литерал `=В'17'` уходит в конец
модуля (`0ЛИТ`).
